# v18 · 分支 A：静态灾难止损（Static Disaster Stop）— 否定性结论

日期：2026-10-02 · 任务 ID：32 · 用户指令优先级 P0

## 用户假设（原文拆解）

> 引入场点锁定的静态灾难止损：止损线一旦在进场瞬间确定（Entry_Price − 4.0 × Entry_ATR，或挂在入场时刻的 Donchian Lower Band），全程不跟随上移。给 5 天的趋势运行留出全部呼吸空间，只有在爆发系统性暴跌或假突破快速破位时才斩仓。测试能否在保留 $2,500+ 利润的前提下把最坏尾部封死。

## 实验矩阵（全部冻结 v17 冠军配置：M30 don55s × long × ATR闸门 × 持5交易日）

**合计 44 个止损变体全部无法保留 $2,500+，且无一真正封死尾部。**

## 三大根因

1. **时间出场本身已是灾难止损**——5 日强制平仓把单笔最大损失封在时间维度（base worst −$168 / p05 −$89 / maxDD −$260）。用户想封的尾部本来就是封着的，−$168 只占 5 年总利润的 5.6%。
2. **MAE 分布无黑天鹅阈值**——5 日动量路径的正常回踩中位 5.7×ATR、p90 15.2×；"灾难"与"正常回踩"在同一连续分布里，任何止损线都在扫正常交易（atr4.0 触发率 59%，8×ATR 仍有 36%）。
3. **止损触发=绞肉开关**——斩仓释放仓位后突破信号在震荡下跌中反复再进场（159→189~307 笔），制造新交易与新亏损尾部；冷却也救不了（被斩后错过真突破的代价远大于避开假突破的收益）。

## 启示（尾部管理的正确位置）

- overlay 纯保险口径：avoided（保险赔付 $2.2~2.5K）< killed（误杀 $0.5~3.6K）全率成立——这是静态止损负期望的最干净证据（零路径耦合）。
- 尾部管理应上移组合层：**波动率倒数仓位**（高 ATR 年小仓）替代价格底线。
- 2026 型单边崩 = 方向敞口问题而非执行问题，解法在多资产宏观 Regime 门控（原第三阶段）。

## 引擎与验收纪律（两 bug 教训后）

- 新增 `EXIT_MODE_TIME_SL`：时间出场为主 + 进场瞬间锁定的静态止损（ATR 倍数或 Donchian 轨道绝对价），全程不上移；触发当根即出场、gap 按更差 open、止损优先于时间出场（同根保守排序）、进场当根同样检查。
- **R1 引擎等价验收**：base 臂与 v17b `simulate_g_jit(EXIT_MODE_TIME)` 输出逐位一致（$2,980.1/159 笔 array_equal）。
- 双引擎互验（纯 Python vs numba 同源编译）全部配置逐位一致。
- 服务器复算：3 脚本 + 3 json 产物 md5 与本地**逐位一致**（pandas 3.0.6 vs 2.2.3 跨版本可复现）。
